# Energy Consumption Prediction System

## 1. Project Overview

The Energy Consumption Prediction System is a web-based application designed to manage manufacturing production data and predict energy consumption for production batches using supervised machine learning.

The application allows users to manage products, machine types, shifts, and production batches. It provides an energy prediction feature and stores prediction results for future reference.

## 2. Objectives

- Manage manufacturing master data and production batches.
- Predict energy consumption based on production parameters.
- Train and evaluate a supervised regression model.
- Integrate the machine learning model with a REST API.
- Store production records and prediction history in a database.
- Provide a user-friendly interface for managing and viewing data.

## 6. Dataset

The application uses a sample dataset stored at:

`data/historical_production.csv`

The dataset contains 500 synthetic production records generated by `ml_service/generate_data.py`.

The columns are:

| Column | Description |
|---|---|
| `quantity` | Number of units produced |
| `machine_hours` | Machine operating hours |
| `machine_type` | Type of manufacturing machine |
| `shift` | Production shift |
| `actual_energy_consumed` | Energy consumption in kWh |

**Data note:** The supplied sample data is simulated for development and demonstration. It is not collected from actual factory measurements.

### Generate sample data

Run this command from the project root:

```powershell
python -m ml_service.generate_data
```

This regenerates the sample CSV file. Retrain the model afterward if you want the saved model to use the newly generated data.

## 7. Machine Learning Model

The system uses a supervised Linear Regression model to estimate energy consumption.

### Input features

- Quantity
- Machine hours
- Machine type
- Shift

### Target variable

- Actual energy consumed, measured in kWh

### Preprocessing

The training pipeline uses a `ColumnTransformer` to process the input features:

- Numerical features are passed through directly.
- Categorical features are encoded using `OneHotEncoder`.

### Training and evaluation

The dataset is split into:
- 80% training data
- 20% testing data

The model is evaluated using:
- Mean Absolute Error (MAE)
- Root Mean Squared Error (RMSE)
- R² score

The trained pipeline is saved to:

`models/energy_model.joblib`

### Train the model

From the project root, run:

```powershell
python -m ml_service.train_model
```

The command prints the training and testing record counts, evaluation metrics, and saved model path.

The previously observed evaluation results were:

- MAE: 12.77 kWh
- RMSE: 16.56 kWh
- R²: 0.9935

These results apply to the current synthetic dataset and should not be interpreted as demonstrated accuracy on real factory data.

## 8. Installation Requirements

Install the following software:

- Python 3.11 or a compatible Python version
- Node.js and npm
- A code editor such as Visual Studio Code

### Install Python dependencies

Open a terminal in the project root.

Create a virtual environment and activate it:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

Make sure the configured database is accessible and any required database initialization steps are completed.

### Install frontend dependencies

Open a terminal in the frontend directory:

```powershell
cd frontend
npm install
```

## 9. Running the Application

Run the ML service, main backend, and frontend in three separate terminals.

### Terminal 1: ML Prediction Service

Before starting the ML service, make sure the trained model exists at `models/energy_model.joblib`.

From the project root, run:

```powershell
python -m uvicorn ml_service.main:app --reload --port 8001
```

ML service URL:

`http://127.0.0.1:8001`

ML API documentation:

`http://127.0.0.1:8001/docs`

### Terminal 2: Main Backend

Open a second terminal in the project root and run:

```powershell
python -m uvicorn backend.main:app --reload --port 8000
```

Main backend URL:

`http://127.0.0.1:8000`

API documentation:

`http://127.0.0.1:8000/docs`

The main backend uses the `ML_SERVICE_URL` environment variable when configured. Otherwise, it defaults to:

`http://127.0.0.1:8001`

### Terminal 3: Frontend

Open a third terminal in the project root and run:

```powershell
cd frontend
npm run dev
```

Open the local URL displayed by Vite, usually:

`http://localhost:5173`

Keep all three services running while using the application.

## 10. API Endpoints

### Products

- `GET /products` — list products
- `POST /products` — create a product
- `PUT /products/{product_id}` — update a product
- `DELETE /products/{product_id}` — delete a product

### Machine Types

- `GET /machine-types` — list machine types
- `POST /machine-types` — create a machine type
- `PUT /machine-types/{machine_type_id}` — update a machine type
- `DELETE /machine-types/{machine_type_id}` — delete a machine type

### Shifts

- `GET /shifts` — list shifts
- `POST /shifts` — create a shift
- `PUT /shifts/{shift_id}` — update a shift
- `DELETE /shifts/{shift_id}` — delete a shift

### Production Batches

- `GET /production-batches` — list batches
- `GET /production-batches/{batch_id}` — retrieve a batch
- `POST /production-batches` — create a batch
- `PUT /production-batches/{batch_id}` — update a batch
- `DELETE /production-batches/{batch_id}` — delete a batch

### Energy Predictions

- `POST /production-batches/{batch_id}/predict-energy` — predict and save energy consumption for a batch
- `GET /energy-predictions` — retrieve prediction history

### ML Service

- `POST /predict-energy` — generate an energy estimate using the trained model

Interactive API documentation is available through each FastAPI service's `/docs` endpoint.

## 11. Prediction Workflow

1. The user creates or selects a production batch in the frontend.
2. The frontend sends a prediction request to the main backend.
3. The backend retrieves the batch's quantity, machine hours, machine type, and shift.
4. The backend sends these features to the ML prediction service.
5. The ML service loads the saved regression pipeline and generates an estimate.
6. The backend stores the prediction in the database.
7. The frontend displays the estimated energy in kWh and updates prediction history.
